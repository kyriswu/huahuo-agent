# 开头处理

开始处理前，必须先完整读取 [Mastra 原生运行与资料协议](references/mastra-runtime.md)。其中规定当前认证用户的定位记忆映射、可用工具和保存边界；再按下文读取专业方法并执行，不能只凭本入口摘要创作。

先完整读取 [开头执行规则](references/开头执行规则.md) 与 [开头处理方法](references/开头处理方法.md)，再按本次范围处理生成、改写或诊断。两份文件是本包的完整专业方法依据；不只凭入口摘要或方法名称开始生成。

按 [受众资料协议](references/audience-context.md) 读取已授权当前项目定位中与受众有关的信息，结合本轮要求判断他们的兴趣、理解基础、关注词语与期待价值，再设计语言钩子及正文能够兑现的承诺。无定位时按本轮受众与材料继续，只有关键缺口才必要补问，不重新访谈。

已有观看情境时考虑开头的接收负担，已有圈层可信细节与误读线索时选择贴切词语，结合本条观看所得确定正文能兑现的观看理由。受众层次、观看情境、观看所得和账号作用不能互相代替，也不把刷视频的场景强行改成开头拍摄场景。信息缺失时继续使用当前材料；这些判断融入各候选，不增问卷或审批，仍不读取或套用个人语言风格档案。

生成或未指定候选的改写：保留全部十六种方法及原固定顺序，每种设计三个实质不同的开头，共四十八个候选。每种方法单独一张表，以编号和方法名作表前标题；表格仅有“文案”“画面”两列、三行候选，不增加编号列、构思说明、声音或节奏栏目。文案必须完整体现该法，关键对象、动作、状态和关系不能只留在画面里；画面只写与该条文案相配的场景、氛围和灯光，不用道具清单替代，也不附配音、音乐、音效、语速、停顿或剪辑节奏建议。每案实际文案必须含针对本条典型用户的精准欲望词或关键词，全部逐案检查。独立调用默认在第十六张表的第三个候选完成后停止，不排序或推荐；主流程分步与一次的交付按下述调用合同执行。只诊断或已选候选的局部修改遵从相应范围；回改后精准词语、对应构思法成立条件、文案独立成立、画面与文案一致与正文兑现均须再次成立。独立调用中，用户明确选择或委托本次采用后才处理采用与必要衔接，明确要求合稿时交全文。

IP第七站或获客第八环节调用时，必须另读 [完整流程调用合同](references/full-workflow-handoff.md)：分步完整给四十八案后询问选择，用户选定后由主流程同轮交完整终稿，不再询问是否合稿；一口气完成已经授权内部完整生成、逐案检查、择优与整合，直接交终稿，不等待选择。两种模式均执行同一十六法原文，不缩减方法或数量。

定位仅用于本次受众适配，不扩展为定位维护或自动写回；不读取、套用语言风格档案，也不通过摘要或其他技能间接引入语言习惯。本轮明确要求正常使用。独立调用及跨技能明确请求均遵循同一输入边界。默认对话交付，不改原始素材文件。

本技能以作者意图与表达自主性为先。尊重用户的立场、情绪、判断和表达力度；除非用户要求求证或批判，不自动纠偏、降温、平衡、道德化或强行成长、和解。普通故事、人物、对白、心理、比喻和情境可以围绕表达目的创作，无需逐项求证或标注待验证。依据要求集中于效果承诺和作为真实证明使用的案例；不得伪造研究、名言出处或实测记录来为观点背书。用户明确要求只整理原稿、只改局部或保留指定内容时仍按范围执行，不能借创作换掉作者的观点。
