# 语言风格保存协议｜Resource Memory

先读 [Mastra 运行与资源记忆协议](mastra-runtime.md)。本项目不使用原包的用户目录、Markdown 当前文件或 Python 保存脚本。认证用户的 `languageStyleProfile` 与 `languageStyleLearning` 是定位记忆以外的独立原生键，沿用服务端 Resource 归属，不由提示词选择用户。

## 一份当前档案，学习资料另分用途

`languageStyleProfile` 承接原 `profile.md` 的职责：相关简短语言世界、有效本人习惯、有效目标／避用／局部句法、必要场景差异与来源索引。已知背景、暂定理解与未来目标分别存放，不从背景推定本人已经具有某种固定口吻。不粘贴完整样文、故事或改稿证据对照。

`languageStyleLearning` 承接原 sources 与 changes 中必要的学习材料：获准原文、改前稿、来源类别／lineage／范围、明确认领依据、候选、停用与替代、支持和反例、短对照、确认范围、保留线索和未决冲突。来源原文保存在 `sources[].originalText`，不是摘要；改稿来源 `correction` 同时保留 `beforeText`。学习记录的 `before`／`after` 只说明本次实际修订，不等于完整版本库。

这两个键会被原生记忆整体注入模型，分层只区分用途，当前没有独立按需检索源库。长原文会占用后续上下文；不能为省略这一影响悄悄改存摘要，也不能声称普通写作不会收到 Learning。普通写作不默认使用原文、候选或停用分析；具体学习或校准才用实际必要片段。

已有混合资料可以按用途只读过滤；即使标为有效，主题、立场、归因和固定结论也不是语言规则。维护只整理获准部分，将原条目与出处保留在 Learning 的适当记录中；无足够实际材料时先交具体整理稿，不声称已经做过完整快照，也不无故删除或自动转存定位。局部更新不要求整理全部旧资料。

## 保存一次学习结果

1. **确认实际授权与材料。** 明确学习任务可沿用范围连续接收材料；普通改稿、讨论或单篇纠正不自动授权长期保存。只处理明确同意部分，拒绝或暂缓时不写当前档案、来源和学习记录，无新变化不反复提醒。
2. **区分来源与同源组。** 七类 `kind` 沿用原方法；本人样文、口述、改稿对照才可支持本人表达观察，外部参考、目标偏好、未知来源与明确认领的 AI 表达分别保留身份。`correction` 必须有前稿 `beforeText`，其他类别不携带前稿；`adopted-ai` 必须有明确认领说明 `adoptionNote`，其他类别不携带它。用户认可一句话不能把整篇稿保存为本人认领样本。
3. **保留原文与引用关系。** 在 `languageStyleLearning.sources` 中保存完整获准 `originalText`、`sourceId`、`lineage`、`scope`、`sourceNote`。同稿变体沿用 lineage，不制造独立样本或脚本去重证明；逻辑编号先核对本 Resource 已有项，沿用既存来源与规则编号，不虚构数据库消息 ID、路径或 SHA256。
4. **形成有效档案与学习记录。** 只将有依据、范围明确且按方法生效的表达选择放入 `languageStyleProfile.activePreferences`；候选、停用、被替代及其理由放入 `languageStyleLearning.observations`。相关背景在 languageWorld 中区分已知／暂定／目标。更新 `sourceIndex`、场景差异及必要 learningRecords，保留未受影响内容、反例和尚有用的候选／冲突。来源入库不等于规则生效，不能把主题频率、固定结论或内容纠正伪装成语言偏好。
5. **提交获准变化。** 使用 `updateWorkingMemory({ memory: { languageStyleProfile: { /* 变化字段 */ }, languageStyleLearning: { /* 变化字段 */ } } })`，只放本次实际修改的键；相互引用的资料尽量同次提交，不覆盖定位与无关记忆。嵌套对象字段合并，数组整体替换，必须保留完整旧数组里的仍有效项；不能只传新增一项而清空已有来源、偏好或学习记录。没有变化不写入。
6. **按实际结果回报。** 工具返回成功后才简述新增／修正／候选条目、适用范围及“已保存到当前用户语言风格记忆”。失败或未调用时提供可复制档案稿，明确未保存。没有独立记忆回读工具，不伪造回读、文件路径、版本与哈希回执；后续请求由框架重新加载当前值。

定位或自述作为背景时，按实际性质选择 `author`、`oral` 或 `unknown`，在 `sourceNote` 说明用途为语言世界背景并保留事实／推演／目标的区别；不把报告措辞当本人用语。明确长期要求可作为 `preference` 的完整原话保存，不连带收录一整篇 AI 稿。

## 原生工具示例

以下仅说明首次保存一条明确长期要求的调用结构，不是用户资料。逻辑编号与各数组必须根据实际当前值生成；已有数据时不能原样照抄而覆盖它们。

```json
{
  "memory": {
    "languageStyleProfile": {
      "activePreferences": [
        {
          "id": "pref-1",
          "basis": "target_preference",
          "type": "local_syntax",
          "status": "active",
          "expression": "口播解释句优先直接陈述原意，非必要少用反问",
          "scope": "面向公众的知识口播解释句",
          "sourceIds": ["src-1"]
        }
      ],
      "sourceIndex": [
        {
          "sourceId": "src-1",
          "lineage": "preference-1",
          "kind": "preference",
          "purpose": "用户明确的长期口播句法要求"
        }
      ]
    },
    "languageStyleLearning": {
      "sources": [
        {
          "sourceId": "src-1",
          "kind": "preference",
          "scope": "面向公众的知识口播解释句",
          "sourceNote": "明确长期偏好，按原话范围生效",
          "lineage": "preference-1",
          "originalText": "以后写知识口播，解释句少用反问，直接把意思说明白，记到长期风格里。"
        }
      ]
    }
  }
}
```

实际维护还应记录获准的 `learningRecords`、受影响规则与依据；示例不要求为了字段齐全编造背景、作者身份、相似度、日期或未讨论规则。

## 停用、替代、混合整理与恢复

停用按实际范围从完整 activePreferences 中移出，将原表达、来源、范围、停用原因等保留为 `observations` 的 `inactive` 项；替代为 `superseded` 时必须提供非空的 `supersededBy` 逻辑规则编号数组，指向实际替代规则。新规则生效依据单独成立，不把拒绝某案当作采用备选。候选采用后同步移出非生效列表并保留本次依据和变更记录；未解决冲突在实际相关范围中保留，不静默抹掉反例。

本项目只有当前 JSON，没有原脚本的不可变版本／历史快照、手改自动备份、预期指纹 CAS、SHA256 自动去重与证据分组、指定版本回滚或文件事务校验。学习记录可以保留实际旧条目与修订原因，但不是受存储层保护的审计日志。PostgreSQL 的字段合并不等于同一数组或同一规则的版本冲突检测；运行中的模型也不会自动收到外部手改推送。

用户要恢复某个旧版本时先说明当前没有历史快照库。仅在实际旧材料可见、归属清楚且获准恢复时，将明确内容作为当前值修订；不能凭聊天摘要重建后冒称恢复了完整历史。资料有明显冲突则先澄清具体差异，保留已有有效内容，不声称过期写入已经被 CAS 拦截。

模型使用原生工具时，项目 Schema 对输入来源、状态与相应必需字段作结构校验；这些约束不证明来源真实或用户已授权。原生 HTTP／程序直接写入需由调用方显式解析项目 Schema，不自动继承模型工具的全部校验。

不会训练权重、后台监听、跨用户合并或自动同步其他平台。方法包始终只读保存通用资料，原文与个人规则只属于当前认证用户的原生记忆。
