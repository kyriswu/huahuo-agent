# 主动维护定位与语言风格｜Mastra 适配

先遵循 [Mastra 运行与资料协议](mastra-runtime.md)。本协议在实际授权内维护当前认证用户 Resource 中的 `positioningReport`，以及风格资料 `languageStyleProfile`、`languageStyleLearning`；方法包不是后台监听器。情境设计可识别真实的长期定位或表达变化，普通创作选择不触发持久化。独立开头、道具、内容升华仍只读受众资料，不因交接而增加风格应用或档案维护职责。语言风格的学习和保存依据已注册的 `an-language-style` 实际方法执行，不把本轮 AI 稿自动学成本人。

本协议只管长期档案的认领和保存。用户的强立场、悲观情绪与绝对化表达不需要被修正或证明客观正确才可创作；单篇故事、人物、对白和场景可围绕作者意图发展，不因本协议的状态区分逐项贴“假设／待验证”标签。它们也不自动成为用户已发生的履历或长期偏好。只有用户明确的长期新选择才形成维护候选；效果承诺与用作真实证明的案例另需依据，不以创作认领替代验证。

## 发现变化并主动提醒

先区分对旧判断的解释、方案比较、事实纠错与拒绝采用。仅要说明理由或比较备选、尚未给出新事实或新选择时，停留在解释，不触发维护提议，不改变采用状态、咨询进度或已存报告。明确纠错、撤回采用或改变长期选择时，按实际影响处理相关修订与状态；写入仍沿用已有授权或具体更新提案，不把一次追问、比较或本篇创作选择记成长期变化。

每次聊到受众、需求、价值、方向、差异化、人设、系列或披露边界，都检查是否实际影响长期定位；涉及有来源的语言背景、明确措辞、避用表达或局部句法变化时，检查是否形成真实长期偏好。普通应用不为此重新访谈或重建语言世界，按含义识别，不要求用户说出技能名或“更新”口令。本篇要求只影响本篇，单次改稿不直接推成永久规则。

确有维护候选时，以本次实际注入的当前 `positioningReport`、`languageStyleProfile` 及必要学习依据为准；本轮明确提供的本人材料可在授权范围作比较，不自动替换已存内容。框架整体注入并非按字段隔离，普通应用不展开样文和学习记录来寻找内容素材，长来源仍增加上下文。当前每个用户各有一份定位与风格，没有按项目／账号分组；存在归属歧义时只澄清必要对象，不能合并不同账号或选择另一用户的 Resource。资料不可见时说明无法比较，不能当作空白覆盖。

在本轮形成具体结论或可供学生选择的修改时，先完成当前阶段成果，再用一小段说明“当前已存内容或缺项 → 建议内容、适用范围”，主动问是否更新。定位咨询可在阶段结论时提醒，不等最终十主题全部完成；普通创作不因提醒启动完整定位或学习流程。只有内容确有新增、修正或冲突才提议，纯复述、无变化和仅讨论他人案例不更新。视频分析中的第三方表现、作品定位与对本人账号的改编建议，不自动成为本人长期判断，也不触发本人档案更新；本人另行明确的长期修正按原授权范围处理。

例如：“现有定位写的是‘自媒体新手’，这次你明确为‘有专业经验但不会表达的人’。要把核心受众更新为后者吗？”风格可问：“解释概念少用反问、直接陈述原意，只用于这篇，还是加入口播的长期表达偏好？”例子不预填成用户资料。已有明确长期保存要求或适用学习授权时，在范围内执行，不重复询问。

## 单一定位报告交付

定位统一为《我的账号定位报告》，保存在当前用户原生 `positioningReport`，供本人阅读与适用后续技能共同使用。报告的生成、获准更新及查询按 [定位报告协议](positioning-report-views.md) 处理，固定13项、第一人称，完整讲清定位内核；初步定位也沿用这份报告，不要求先完成十主题，缺项原位保留真实状态。只在内部读取定位或普通聊天中提出更新建议，不自动附送报告；明确只看某章或简短回答时遵从本轮范围。

一次获准定位保存只以原生工具更新这份正式报告中获准章节，保留有效旧内容与无关章节，工具成功后才说明保存结果。查询只读，不因格式更新修改记忆。已有报告依真实内容使用；获准整理或更新时，将指定材料中可追溯内容合入对应章节，保留来源、采用状态与缺口，不补造遗失原文。当前不提供不可变历史、文件回读、指纹绑定或同章版本冲突检测。定位和风格是不同授权范围，确认一类不能推定另一类已获准；本轮表达调整也不自动授权长期学习和保存。

主攻层、另外两层的连接范围、长期公开内容策略或具体表达边界发生变化，也属于定位修订候选；只复核依赖这些变化的需求、价值、内容方向与引导，不清空无关成果。单条面向其他层、一次尝试知识或生活内容、暂时省略商业引导，不自动成为长期策略变化；未确认的规则判断不能写成平台已批准。观看情境、圈层理解、观众具体所得或内容对账号作用的变化，同样只在形成长期事实或明确选择时进入维护候选；它们不由一次创作推断自动成立，也不固定绑定某一受众层。以上仍受本技能的读取、维护权限和保存授权约束，不为开头、道具、升华新增维护职责。

## 确认范围与提醒次数

- 用户明确说“更新进去”“记入定位”“这是长期表达要求，记住”等，或明确同意刚展示的更新提案，即可在该范围执行，不再要求手动调用另一技能或二次确认。同意紧接具体保存提问的“可以”可承接；对内容的一般赞同不自动视为保存授权，“继续”只按原任务范围理解。
- 未确认的建议只留在当前对话；不同意、只改本篇、暂缓或没有回答时，不写当前档案、候选文件或历史记录。同一话题同一差异只问一次，有新变化或学生主动要求再处理；不靠换一句话重复提醒。
- 已明确授权的建档、连续学习或持续保存任务，沿用授权直接保存实际变化；没有变化不更新。不要把维护提醒变成这些任务的重复审批。
- 定位与长期风格都需修改时，合并列明各自范围，允许只批准其中一类；确认一个不推定另一个获准。两类分别按实际工具结果回报，不冒称未成功的部分已保存；未回答的提案不阻塞独立创作。
- 假设、助手建议、未来设计、外部参考与用户事实保持各自性质。单篇语气、临时活动人群不自动永久化；采用一种表达目标只记为目标偏好，不宣称是已观察到的本人习惯；同意规则不等于认领整篇 AI 稿或第三方经历为本人样文。

## 确认后的原生定位维护

已明确授权的局部定位修正可由本技能直接衔接原生保存；需重新推演完整定位时，使用实际已注册的深度定位技能。用户无需再次选择技能或重复批准同一范围。普通局部维护不启动十主题咨询，不改无关进度。

只有获准形成或重新综合正式总报告时，按 [定位报告协议](positioning-report-views.md) 对齐相关结论和必要原料；局部维护只核对受影响的原话、例子与纠正。已有上下文不重复索取，原料不在上下文且无可用读取工具时说明依据范围，仅请求会影响判断的必要材料，不冒称回查全部历史。

1. **核对再改。** 以本次实际注入的当前 `positioningReport` 与获准提案为依据，保留手工修改和无关有效信息；实际冲突影响获准内容时，展示差异再澄清，不以旧聊天覆盖。正在运行的模型没有外部更新的实时推送，也没有预期版本 CAS，不声称已经做了不存在的并发核验。
2. **保留完整性。** 将实际变化归入对应13项的完整章节正文，保留用户事实、专业推演、未来设计、采用状态和开放问题；局部确认不把整份建议稿标成已采用。只复核依赖变化的受众、需求、价值、方向、表达与披露边界，保留其他成果。不能把临时情境、故事、台词或背景推测升级为真实履历和长期选择。
3. **提交局部变化。** 调用 `updateWorkingMemory({ memory: { positioningReport: { /* 获准章节 */ } } })`，只提交实际变化；不传整份空模板、不改其他记忆 key。嵌套对象按字段合并；数组整体替换，更新来源时保留实际仍有效条目，不仅传新增一项。原生 Schema 的13项字段见 [运行协议](mastra-runtime.md)。
4. **按实际结果回报。** 工具成功后才简述更新章节和“已保存到当前用户定位记忆”；失败、未调用或资料不足时交付可复制更新稿，明确未保存。当前仅保存 JSON 当前值，不制造历史快照、版本编号、文件路径、哈希、下载链接或回读回执。
5. **继续当前创作。** 定位保存不自动重写旧作品、不代表同意新的情境或下一主题。后续请求由框架加载当前值，只复核受影响判断；查询保持只读。风格使用自己的两个记忆键，不混入定位；当前没有独立作品库，不能把任何长期记忆当作作品仓库。

## 确认后的原生风格维护

维护风格前加载已注册的 `an-language-style`，读取其学习与保存协议；样文学习、停用／替代、查看依据或处理冲突由该方法衔接，不发明来源类型或额外工具。当前有效档案是 `languageStyleProfile`，来源与学习记录是 `languageStyleLearning`。

1. 以实际资料和获准范围为依据，区分已知背景、暂定理解、目标，本人习惯与目标偏好。只维护具体措辞、明确避用和局部句法，不把主题、观点、故事、宏观结构、因果或结论写成风格规则；暂定背景不升级为本人事实。
2. 来源保留实际 `author`、`oral`、`correction`、`external`、`preference`、`unknown`、`adopted-ai` 身份与同源关系。获准保存的来源保留完整 `originalText`，改稿来源保留真实 `beforeText`；明确认领 AI 表达只按认领范围作目标参考，不将“这稿可以”解释为全文认领。没有实际原文或认领依据不能编造，重复修改同一原稿不冒称多个独立样本。
3. 仅有效且范围清楚的表达进入 `languageStyleProfile.activePreferences`，保留场景差异与真实来源索引；候选、停用、被替代及其原因、必要短对照、学习记录和未决冲突留在 `languageStyleLearning`。不删除尚有用的候选或旧依据，不用新样文一概覆盖有效偏好。
4. 通过原生 `updateWorkingMemory` 只提交获准的 `memory.languageStyleProfile`／`memory.languageStyleLearning` 局部字段，不带空模板、不改定位及咨询进度。嵌套对象合并，数组整体替换；更新任何来源、偏好、索引或记录数组时提交仍有效的完整数组，保留无关旧项。不得伪造工具、消息 ID、版本、时间、哈希或实际未读取的路径。
5. 工具成功后才简述保存的具体内容及范围；失败、未调用或授权不足时，交付可复制稿并说明未保存。当前保存 JSON 当前值和普通学习记录，不是不可变历史、SHA去重、独立样本自动计数、文件回读、CAS或历史恢复。后续请求由框架加载当前值，运行中不提供外部修改的实时推送。

普通情境台词只读应用有效风格，AI 成稿不自动回收入库，本篇要求不永久化。没有实质变化不更新；拒绝或暂缓无新变化不反复询问。风格保存不意味着重新改写旧作品，也不代表用户确认整份定位。

没有报告且确有长期定位新内容时，先完成当前创作，再提出一次具体初版保存建议；确认或已有相应授权后，只保存已讨论部分，其余保留真实未确定状态，不能编造完整定位或本人习惯。明确不保存优先，无新差异不反复提醒。方法包只保存方法，不写入用户资料、不跨用户或账号混用，也不创建常驻任务或承诺后台同步。
