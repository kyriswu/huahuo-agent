# 情境设计｜来源与 Mastra 适配

来源：用户提供技能包中的 `an-situation-design` 1.4.1（安先生 AI）。课程来源和默认交付规则仍见 [方法来源](sources.md)。本项目没有重新发明情境方法，也没有将专业正文压缩成入口摘要。

## 保留的专业材料

- [情境设计方法](情境设计方法.md)：完整主体、六条规则、四案设计与匹配开头、比较邀选和选后全文融合。只改宿主资料入口、持久化及情境卡库的实际能力边界。
- [四方案](four-situations.md)：2＋2、组内差异、人群比较、关系与时间区分；只把首段项目报告读取改为原生定位输入。
- [情境卡](situation-card.md)：原文保留的十二项内部检查、生活切片和融合检查。
- [语言风格交接](language-style-handoff.md)：保留表达与内容分开、作者意图、用词与局部句法等原则；当前有效档案映射为 `languageStyleProfile`，来源与学习资料映射为 `languageStyleLearning`，本轮要求优先，长期维护衔接已注册的语言风格技能。
- [资料交接](student-project.md)、[主动维护](profile-updates.md)、[定位报告](positioning-report-views.md)：保留定位应用范围、长期变化识别、确认与保存边界、固定13项完整报告；文件操作改为本项目实际原生记忆能力。
- [验证要求](validation.md) 与 [使用说明](../使用说明.md)：保留创作行为验收场景并更新 HuoX 入口。规范、静态测试和模拟模型链路均不代表真实模型创作质量已验收。

## 明确的适配差异

新增 [Mastra 运行与资料协议](mastra-runtime.md)。定位使用当前认证用户注入的 `positioningReport`；获准的长期定位修正调用原生 `updateWorkingMemory` 局部更新。语言风格使用 `languageStyleProfile`、`languageStyleLearning`；情境台词应用有效表达，长期学习与维护按 `an-language-style` 实际协议及授权衔接。框架整体注入各类记忆，分键仅区分用途，长样文仍增加上下文；不能声称物理隔离或按需加载。

当前每个用户各有一份定位与风格，没有原文件历史快照、SHA256消费者绑定、同字段预期版本冲突检测、自动哈希去重／独立样本计数、历史回滚或账号／项目分组。仍没有独立情境卡／作品库或用户文件读写工具；作品保存请求只能依实际能力交付本轮可复制成果，不能把风格来源归档冒充作品库保存。

不携带原宿主的 `agents/openai.yaml`、`_user_meta.json` 或原 `source-map.json` 文件哈希清单；前两者不是本项目调用第三方服务所需配置，旧哈希也不能证明适配后文件完整性。本文件是迁移与来源索引，不伪造原包校验结果。
