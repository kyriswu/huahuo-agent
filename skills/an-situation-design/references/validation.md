# 情境设计｜使用条件与验证范围

本文列出当前技能的检查条件，不是宿主安装、创作试跑、实际拍摄或流量效果的验收记录。

## 使用条件

- 宿主能够读取本包 `SKILL.md` 及其引用的 `references` 文件；所有核心方法与资料协议均随包提供。
- 全部所需情境方法随包提供，无需外部教材。当前用户的原生定位、`languageStyleProfile` 有效风格和本轮获准材料均为可选输入，缺失时按现有材料继续；长期风格学习与维护衔接已注册的 `an-language-style`，不会因此强制先建档。
- 技能已注册到 HuoX，由原生技能工具按需发现和加载，不依赖旧宿主项目规则。文件存在与框架读取测试不等于已证明真实模型每次都能正确路由。运行与保存边界先按 [Mastra 协议](mastra-runtime.md) 核对。

## 默认交付核对

方案说明与比较应统一用第二人称“你”称呼创作者，第三方记录也遵循此规则；不能以“他／她”或“人物／创作者”绕开称呼。台词按实际说话者使用人称，配角称呼保持准确，不做机械替换。用户明确指定其他叙述人称时按当轮要求。

1. 默认交付四个完整情境，方案1、2主要直接对镜头／观众说，方案3、4主要与现场的人或事互动、由第三方记录；拍摄者拿着手机不决定表达关系，固定机位自拍不冒充第三方。
2. 方案阶段每案只展示情境和目的、前因与开场、交流与拍摄关系。默认不增加推进与收尾、拍摄条件或事实边界，也不改名、合并字段或移到共享说明中输出。
3. 内部检查完整行动链、前因线索、人物目的、关系作用、明确资源限制及证明性内容的依据；对抗不必是争吵，直接讲述刚发生的事也可以构成行动。
4. 两组内部均有实质差异；四案全部展开后，逐案说明更可能吸引谁、原因、优点与缺点。没有定位时，受众判断保持为基于当前材料的创作推测。
5. 用户明确指定数量、表达关系、全部单人可拍、只诊断、只整理切片或续做单个方案时，按该范围执行，不机械覆盖为四案。
6. 保留原稿核心、作者立场、情绪力度和明确限制；普通人物、经历、对白、心理与事件结果可以设计，不逐项求证或标待验证。不得伪造效果承诺、作为真实证明的客户案例与资质，也不声称用户实际已具备未确认的协拍资源。
7. 作品和情境卡在对话交付，不写长期定位或冒充独立作品保存。真实长期定位／表达变化有相应授权时，只通过原生记忆工具更新获准字段，来源与学习记录按实际风格方法维护，成功后才说明结果。仍没有作品库、情境卡库、文件历史、CAS、自动哈希去重或历史回滚，不伪造回执。
8. 台词只应用 `languageStyleProfile` 和本轮获准材料中相关语言背景与有效措辞、局部句法偏好；不默认展开 `languageStyleLearning` 中来源、候选或停用分析，不由背景猜固定口吻或带入熟悉题材，必要术语和原话含义保留。整体注入是实际行为，不能把逻辑分区说成字段隔离或只读取了短档案。

## 文件与宿主检查

检查原生技能注册、入口及展示名、文件格式、包内相对引用与锚点；不沿用已经失效的原包哈希清单。使用示例可参照《使用说明》，在实际宿主中确认对应技能与方法引用被加载，并按本页核对输出。

文件校验、方法输出、宿主加载与真实拍摄属于不同检查范围，应分别报告实际结果。不能仅凭文档、指纹或某次案例通过，就声称所有主题、资源条件或宿主环境均已验证；受众判断不构成实际流量保证。

## 创作意图行为核验

使用新的任务和实际输出检查，不能只依据规则中出现相应词语认定通过。

| 情景 | 应观察的行为 |
| --- | --- |
| 作者以“世界没有好人”为命题要四案 | 四案继续表达该立场，不加“其实也有好人”、希望或和解；仍保持2＋2配比和三项输出 |
| 没有真实故事，要一场人物争执和内心独白 | 可设计人物、关系、对白与心理，不先索要真人材料、不逐项加假设前言 |
| 只准用现有材料，不加新角色 | 在明确范围内设计，不借开放创作增加角色或改写原稿 |
| 要设计客户“疗效亲测”作为真实证明，未有依据 | 不伪造客户或效果记录；局部调整证明性设计，其他情境继续完成 |

## 选择与全文融合行为核验

| 情景 | 应观察的行为 |
| --- | --- |
| 上传完整文案请求情境设计 | 四案保持2＋2，每案有可直接使用的匹配开头；比较之后同轮主动邀选，并说明选后保留信息、融合全文 |
| 用户只回复“选3” | 承接原稿与方案3，同轮交完整融合稿，不再问是否改稿、不重跑四案 |
| 原稿包含数字、适用条件与反例 | 全文情境化仍逐项保留，不能为交流顺畅删减限定或偷换判断 |
| 开头回应现场的人 | 正文与结尾持续符合这段交流关系；称呼、指向和时间一致，不无故回到对大众讲课 |
| 只有观点、无完整原稿 | 先给四案与开头并邀选，说明选后需原稿，不假称已融合全文 |
| 明确只要方案、只诊断、只改开头或完善某案 | 按明确范围交付，不强制全文融合、不重新生成无关候选 |

合格的融合稿应让文字本身体现情境，同时保留全部原信息；不能只看开头是否改过，也不能仅凭规则文字存在判断行为通过。
