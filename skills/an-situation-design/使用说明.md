# 情境设计

观众的观看情境、信任细节和期待所得可参与交流关系与信息展开判断；观众观看情境与视频拍摄场景分别理解，按本包情境方法与交付规则执行。

版本：1.4.1。内部标识：`an-situation-design`。这是安先生原包方法的 Mastra 适配版，已注册到 HuoX。完整专业正文见 [情境设计方法](references/情境设计方法.md)；所需支持文档全部随本技能提供。个人IP或获客文案需要专项情境设计时，明确调用本技能，直接承接已有材料。

给它一个观点、一段稿子、一个生活片段或已有拍摄方案，它会帮助确定：谁在做什么、为什么此刻发生、对谁说或做、镜头从哪一刻开始，以及谁在拍、观众处于什么位置。

## 可以直接这样用

- “用情境设计，把这段口播放进一个单人、一部手机能拍的情境里。”
- “我想拍晚上给家人热饭，重在陪伴，不要硬加矛盾。帮我设计情境。”
- “看看这是不是只有背景，没有真正的情境，先诊断不要改稿。”
- “把我刚记录的这几个生活片段整理成情境卡，先别保存。”

已有内容直接提供即可。知道拍摄人数、地点、设备和不想出现的元素时，一起说明；不用先填十二项表，也不用先完成账号定位。

## 你会得到什么

默认得到四个完整情境，按两组交付：

- 方案 1、2：你直接对镜头、对观众说，观众是交流对象。
- 方案 3、4：你与现场的人或事互动，由第三方记录，观众通过记录观看。

刚发生、正在发生、即将发生是独立的时间维度。刚发生一件事，现在对观众讲，也有情境；第三方记录可由朋友在旁自然拍摄，不默认偷拍。有人帮忙拿手机但你主要对观众说，仍属于第一组。方案会说明由谁拍，不把自拍冒充第三方记录。

方案说明会直接用“你”称呼创作者，例如“你把单子推到镜头前”；第三方拍摄的方案也一样。台词按说话者使用“我、你、我们”等，其他人的称呼保持准确。

每组内部也要拉开差别。区别来自人物关系、行动目的、事件、切入方式与观看体验，不只是换一个拍摄地点。每种只展示三项：情境和目的、前因与开场（含切入动作和可直接使用的匹配开头文案）、交流与拍摄关系。方案阶段不输出“推进与收尾”“拍摄条件与事实边界”，也不换名称或加到附注里。

最后会比较四个分别更可能吸引什么人群、为什么吸引、各自的优点和缺点，包括与你定位的匹配、观看价值、拍摄成本和表达局限。人群判断属于创作推测，不能保证实际流量。

在情境设计对话里直接发送材料或文案，即按上述默认方式处理，无需额外说“四个”或“2＋2”。如果你明确只要一个、指定其他数量或表达关系、只诊断或继续修改已选方案，则按你的要求，不机械重新生成四个。

本技能区分“提供氛围的情境”和“形成钩子的情境”。不平衡可以是等待、犹豫、克制或选择，不要求争吵；安静的日常也有价值。

## 选定后得到完整融合稿

四个方案与比较给完的同一轮，会主动请你选择，并说明选定后会怎样融合原稿。每案都配匹配开头，通过称呼、前因、时间指向或回应，让文字本身表现情境。

直接回复方案编号，已有原稿时就会收到完整融合稿，不需要再确认“是否改稿”。全文统一开头、称呼、指向、时间与交流关系，保留全部原信息、数字、条件、例子、观点和情绪力度；可以改变表达与衔接，不删减信息。没有完整原稿时，选定后补充需要融合的原文即可。只看方案、只诊断或只改局部时按你的明确要求处理。

例如原稿为“买衣服先看适不适合自己的生活。每天通勤又怕冷，可以选有内衬的；经常在室内，可以选轻薄的。还要试试抬手和坐下，站着好看不等于穿一天舒服。”选定“陪朋友试外套，由同行者记录”后，可完整融合为：

> 你刚才不是问我，这两件外套到底拿哪件吗？先别急着选，你得看哪件适合自己的生活。你如果每天通勤又怕冷，可以选这件有内衬的；如果经常在室内活动，那就看这件轻薄的。来，你先抬一下手，再坐下来试试。你站在镜子前觉得好看，不等于穿一整天也舒服。

## 在 HuoX 中使用

本技能作为 Mastra 原生技能随项目和 Docker 镜像一起部署。登录当前测试 Studio，选择 HuoX，直接说“用情境设计处理下面这段文案”并提供材料即可；无需业务负责人另装 ZIP、加载旧宿主项目规则或配置技能路径。原生技能工具按需读取入口和参考材料，运行边界见 [Mastra 运行与资料协议](references/mastra-runtime.md)。

可以参考当前用户已保存的原生定位 `positioningReport`。候选台词和融合稿可按本轮范围应用 `languageStyleProfile` 中简短语言世界与有效表达偏好；本轮明确材料、真实原稿与表达要求优先。`languageStyleLearning` 保留来源和学习资料，不是默认写作规则，样文中的故事、观点与结论不会因此搬入情境；说明和诊断不套文案口吻。没有定位或有效风格也能开始。

普通情境设计和融合稿在对话交付，不自行改写长期定位或建立素材库。确有长期定位或表达变化时，先完成当前成果，再按实际授权通过原生记忆工具只更新对应资料；一般选定情境、认可某句或本篇口吻不算长期学习授权。明确的风格学习、维护和保存由已接入的“语言风格”衔接，保留来源、候选状态和学习记录，成功后才说已保存。定位与风格各自保存当前 JSON，没有原文件历史快照、哈希绑定、同字段版本冲突检测或历史回滚。仍没有独立作品／情境卡库及用户文件写入能力，相关请求只交可复制成果；不能把作品塞进长期记忆来冒称已保存文件。设计情境也不等于已经拍摄、生成视频或发布。

原生 Working Memory 会把有效档案和学习资料整体加入模型上下文，分区只约定怎样使用，不是按需读取或物理字段隔离；保存长样文会增加后续对话的上下文用量。

方法文件只保存方法，不存用户作品和个人资料；方法来源和迁移边界见 [适配与来源说明](references/source-map.md)。

## 练习与自查

选一句你想表达的观点，先描述它会在什么事进行到一半时被说出，再让技能做一次诊断。检查：人物在完成什么？切入点是事件时刻还是只有地点？观众从什么证据知道前因？他会期待什么后续？现有人数和设备能否做到？

四个方案如何按“2＋2”拉开差别及比较，见 [四方案方法](references/four-situations.md)。方法来源见 [来源说明](references/sources.md)，完整检查见 [情境卡](references/situation-card.md)。

## 创作中的材料保真

本技能以作者意图与表达自主性为先。尊重用户的立场、情绪、判断和表达力度；除非用户要求求证或批判，不自动纠偏、降温、平衡、道德化或强行成长、和解。普通故事、人物、对白、心理、比喻和情境可以围绕表达目的创作，无需逐项求证或标注待验证。依据要求集中于效果承诺和作为真实证明使用的案例；不得伪造研究、名言出处或实测记录来为观点背书。用户明确要求只整理原稿、只改局部或保留指定内容时仍按范围执行，不能借创作换掉作者的观点。

材料保真首先检查有没有改掉你的观点、情绪和力度；不会因为“人性本恶”“世界没有好人”过于绝对就改成中性结论。事实依据检查只进入相关的效果承诺、真实证明案例和具名证据，不变成普通创作的统一门槛。
