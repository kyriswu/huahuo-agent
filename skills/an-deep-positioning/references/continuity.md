# 进度与资料

先遵循 [Mastra 原生运行与记忆协议](mastra-memory.md)。当前用户的 `positioningReport` 保存正式定位正文，`positioningConsultation` 保存必要咨询状态。框架自动注入当前记忆；不查用户目录、不运行本地脚本、不创建磁盘会话快照。

## 当前会话与跨会话

仅当前对话即可开始。跨会话报告和进度只在入口2的初次建档、明确保存请求、具体提案获准或已有持续保存授权范围内写入。创建初步报告不要求初始化整个深度咨询状态；只保存用户已描述内容，缺项如实保留。报告 `stage: initial` 不代表咨询完成，保存也不表示用户同意继续深化。

用户只要求阶段交付时当轮给一份完整可复制报告，不以写入确认为退出门槛。仅暂停时保留本轮续做位置，不强制交报告；明确下一步、换主题或局部跳过时按实际选择继续，不能把跳过记为完成。

[session-template.json](session-template.json) 仅为字段语义的空白示例；原 `consultationState` 的字段平铺到 `positioningConsultation`，再保留 `needsReviewSubjectIds`。不要把模板空值写入已有用户记忆，也不使用旧 `revision`、磁盘 `reports` 路径或 `schemaVersion`。

## 状态语义


- `exploring`：还在形成当前判断。
- `provisional`：已有够用第一版，尚未被用户采用；是否转向另行记录。
- `accepted_for_now`：用户采用当前版本；不代表其中推演变成事实。
- `revising`：正在修正已有判断。
- `mode` 为 `deep` 或 `simple`；简单模式用 `simplePhase` 记录候选与建构阶段。
- `currentSubjectId` 是实际当前主题；`recommendedNextSubjectId` 只是建议。默认深度后继以 [入口](../SKILL.md) 的顺序表为准，允许用户明确交叉或跳转；快速候选默认后继为 `quick_construction`。最后主题后继为 null；跳到最后一项不意味着前面已完成。
- `userDecision` 保留用户明确选择的原话或准确摘要；单纯“嗯”“不错”不能被改写成继续决定。
- `resumePoint` 保存回退或局部跳过前的位置及剩余工作；`dependencies` 记录哪些判断依赖哪些事实或主题；`needsReviewSubjectIds` 标出受新信息影响的后续主题。未解决依赖限制相应结论的确定性，不阻止先讨论不依赖它的材料。
- `confirmedMaterial` 保存相关事实和来源，不把未来设计放进去。专业推演、开放问题、定位边界与方向假设有各自字段。
- `subjectAssets` 只保存实际讨论主题的简明结论，未到达主题留空。初步档案可以记录用户已描述的其他方面，但不据此把相应深度主题标为完成，也不把意向塞进事实字段。先聊创作者时可保存实际形成的创作者素材；尚无受众判断时，`audience.core/seed` 留空，校准路径记入 `positioningHypotheses.firstUser`，不为遵守默认顺序伪造受众。
- `recovery` 暂时保存触发原因、进入点与返回点；恢复本身不改 `currentSubjectId`、不把主主题记为完成；用户在恢复中明确转向则更新实际主题并保留原点，回归或退出恢复后清空临时恢复字段。局部跳过和拒绝当前话题不是低信息恢复触发。

每次诊断、修订、主题交接或用户导航选择改变理解与进度，都更新会话状态或当前对话的续做摘要。明确导航时，即使本轮只是新主题的首组问题，也更新实际当前主题、决定、建议后继与返回点，保留已接受资产。只有达到该主题够用标准且用户明确采用时，才加入已完成项；“下一步”“跳过”“先聊别的”不自动成为采用决定。纯寒暄、无诊断的首次采集、只读审阅、纯解释及没有新增判断的比较不需写状态；求解释本身不改变当前主题、完成状态、采用状态或恢复点，比较中的新推荐也不自动成为采用。持久化仍以既有保存授权为准，按原生记忆协议提交 `positioningConsultation`。

纠错记录用户实际修正的原意和受影响结论；助手原先误读不记成用户改口。拒绝未采用建议保留“未采用”及必要原因，撤回已有选择则记录实际撤回范围，只复核相关依赖；不新增状态枚举、不清空有效资产、不自动采用备选。按 [咨询方法](consultation.md#先分清解释比较纠错与拒绝采用) 分别处理对话意图和导航。

“导航回执”指更新实际咨询理解与当前会话的简明续做摘要；有进度保存授权时同步 `positioningConsultation`。只有原生工具成功才称已保存；暂不保存时在当前对话承接。

产品与业务沿用现有状态结构，分别保留以下信息，不为这些判断额外扩展咨询状态字段或专业主题，也不只依赖会被后续导航覆盖的 `userDecision`：

- 产品或业务的已有、筹备、明确没有、未确认状态，以及已确认事实与来源，放入 `confirmedMaterial`；筹备事实只说明正在筹备，计划中的客户、效果与结果仍为未来设计。
- 它与受众探索的关系：当前是候选入口、适配约束、暂不参与还是未确认；有依据的判断与尚未成立的关系分别进入现有专业推演、方向假设、开放问题和依赖。
- 它与生命体验、内容支撑的关系：实际经历、判断与资源可以支撑什么表达；不把经历自动变成受众、能力或市场证据。
- 变现意图及其范围：明确想做、暂不做、备选、未定或暂跳过，连同用户原意保留；变现未定不阻塞其他主题。
- 逐主题进度：已讨论且采用、已有暂定版、正在修订、未聊、局部跳过及返回点。只使用现有主题状态、完成列表、开放项、`resumePoint`、`dependencies` 和续做摘要表达，不新增枚举，也不把未聊或跳过写成完成。

`userDecision` 记录当次明确导航或选择；关系与事实同时进入上述既有位置以及续做摘要，后续一句“继续”不能覆盖原先的产品关系。正式报告的独立“产品与业务”维度同步保留状态、三类关系、依据与缺口；未问/未答不能写成没有，不因有变现意图就设定购买受众。获准保存时按现有协议同步，未获保存授权时仅在当前对话承接。

## 层次与公开策略的状态

受众至少三层、主攻与另两层连接、公开内容目的及相关边界沿用现有事实、专业推演、方向假设、开放信息和依赖记录，不为这些判断额外扩展咨询字段或枚举。真实依据与用户明确选择分别保留；三层模型可为推演，主攻建议未采用就不写成长期决定。公开策略保留已核验条件、来源日期与待核验范围，不能仅因职业或“科普”措辞记为已允许。

观看处境与注意力、圈层可信细节及误读、具体观看所得、内容对账号的作用按实际讨论归入现有受众、价值和传递资产及来源说明；不为每项新增必填字段。受众层次、观看所得和账号作用分别保留含义，不能从外层推定拉新、从内层推定成交，也不把预期感受或关系写成已观察结果。

续做摘要交代当前分层、主攻是否采用、另两层连接、公开内容目的和会影响后续的条件；材料不足、未聊或跳过保持原状态，单篇面向延伸层不改长期主攻。用户变更主攻或公开策略时只复核实际依赖的洞察、价值、方向、表达和边界；没有变化不制造版本，查询已有报告不自动补三层或核验。

## 修改与续做

续做先使用当前注入的 `positioningReport`、`positioningConsultation` 和报告末的实际续做信息；只有报告而无进度时，从其待完善部分继续，不编造精确上次主题。用户更正后定位最早受影响主题，仅在 `needsReviewSubjectIds` 标记实际依赖的后续判断，保留真实创作者经历、无关成果和原返回点。

例如核心用户由“职业转型者”改为“刚任管理岗者”，用户洞察、价值、类型、竞争、传递、人设及综合只按实际依赖重评，不机械清空全部资料。原报告中仍引用旧受众的相关章节不能假称已经复核。

## 原生保存

报告与进度按 [原生记忆协议](mastra-memory.md) 分别提交相应对象的局部字段。报告章节保存完整有效正文，来源和完成列表等数组整体替换时保留仍有效条目。每次工具成功后如实说明本次保存范围；失败则给未保存稿与续做摘要，不声称已持久化。

本次原生配置只保存当前 JSON；不提供原脚本的文件锁、expected-version CAS、不可变历史快照、路径绑定或文件回读。保留的聊天消息不等于逐次报告版本库，不虚构历史版本号、文件链接或脚本回执。

## 共享定位的阶段与局部更新

按 [定位主动维护](profile-updates.md) 在本轮具体结论后处理真实变化；已有明确保存授权直接写入获准范围，无授权则只提出一次具体差异。只查询、解释、比较、诊断或暂不保存不写记忆；报告保存不自动改变咨询主题或用户采用状态。定位与风格是独立资料；语言风格已由 `an-language-style` 使用 `languageStyleProfile`、`languageStyleLearning` 接入原生记忆，普通定位任务不套用或维护风格，另行明确的独立请求才按其范围衔接。

## 报告交接与查询

正式交付按 [定位报告协议](positioning-report-views.md) 与 [报告模板](../assets/定位报告模板.md) 展示第一人称13项正文，用户与后续技能共用 `positioningReport`。已有内容完整保留，缺项原位标注，初步稿不代表十主题完成。

正式综合前按 [决定性材料回查](consultation.md#正式综合前回看决定性材料) 优先使用当前记忆和本轮材料；原话缺失且当前没有历史检索工具时，只请求必要材料，不声称已经回查。查询直接提供当前已保存报告的所需内容，不运行状态初始化、不生成版本、不修改进度，也不补造丢失历史。
