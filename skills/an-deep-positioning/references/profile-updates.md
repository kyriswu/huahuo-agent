# 主动维护定位

先遵循 [Mastra 原生运行与记忆协议](mastra-memory.md)。本协议维护当前认证用户的 `positioningReport`，不扫描目录、不运行脚本，也不建立后台监听。HuoX 已另行注册 `an-language-style`，以 `languageStyleProfile`、`languageStyleLearning` 承接风格资料；普通定位任务不套用个人风格、不顺手学习或更新它们。本轮明确表达要求可以用于本轮；另行明确的独立风格请求按该技能及实际授权衔接，不扩大定位保存范围，不把定位推演冒充本人表达证据。

## 只记录真实的长期变化

定位先尊重作者立场、情绪和表达方向，不要求观点被修正或证明客观正确才可创作。人物、对白和未来场景可以设计；创作被选用不自动变为用户已发生的履历或长期偏好。只有用户明确的新事实、纠正和长期选择才形成维护候选；效果承诺和用于真实证明的案例仍需依据。

先区分解释、方案比较、事实纠错、拒绝采用和撤回旧选择。仅问原因、比较备选或讨论他人案例时，不改变当前报告、咨询进度或采用状态；对助手误读的纠正不能记录成用户改口。拒绝未采用建议不清空其他成果、不自动采用备选。

每次涉及受众、需求、价值、方向、差异化、人设、系列和披露边界时，按实际影响检查当前定位。不为维护而重新访谈或补齐所有章节；已确认的公开内容目的、受众层次和行业外兴趣等发生变化时，只复核有依赖的洞察、价值、方向和表达，保留无关有效内容。单条内容面向其他人群、临时语气和一次试做不自动改变长期定位。

## 授权范围

- 入口2“已有想法，先写入定位档案”、明确要求保存/更新、确认刚展示的具体修改提案或已有持续保存授权时，直接在获准范围调用原生工具，无需重复确认或再选另一个技能。
- 仅描述想法、一般赞同、“继续”或只要解释、比较、诊断、阶段成果不自动授权保存；用户明确暂不保存优先。
- 尚无保存授权但确有长期变化时，先完成当前成果，再用一小段展示“当前已存内容或缺项 → 拟更新内容、适用范围”，只询问一次是否保存。无变化不制造更新；拒绝或暂缓后无新变化不换句话反复追问。
- 初次建档授权不自动延伸为持续保存、下一主题推进或独立风格维护。只有形成够用结论且用户明确采用，才按真实情况更新采用和完成状态。

例如：当前核心受众是“自媒体新手”，本轮用户明确为“有专业经验但不会表达的人”，在获准范围将变化完整归入 `coreAudience`，并按实际依赖修订 `audienceNeeds`、`coreValue` 或 `contentDirections`；不把一次修改当作所有章节都需重写。

## 原生保存步骤

1. 使用当前注入的 `positioningReport` 与本轮获准材料，保留关键原话、依据、例子、选择和开放问题。已有内容完整时不重复索取；仅有片段时不补造原始全文。
2. 将获准变化归入13项的对应字段，提交该章节完整有效正文；事实、专业推演、未来设计和采用状态自然保留，不能因第一人称把建议改成事实。
3. 使用原生 `updateWorkingMemory` 提交 `memory.positioningReport` 局部字段；来源、阶段、采用状态按实际维护，不改无关记忆 key。需要同步获准的咨询依赖与恢复点时，单独提交 `positioningConsultation` 的相关字段。
4. 只在工具成功后说明已保存及本次范围；失败则保留当前成果并明确未保存。不生成磁盘路径、报告版本号、历史快照或脚本回执，不声称具有未实现的并发版本检查。
5. 保存不自动重写旧作品、不启动完整定位流程、不代表用户同意继续。后续请求由框架加载当前值，查询与普通解释保持只读。

无已有报告时，只写本轮确实讨论的部分；缺项维持未讨论、已跳过、暂未回答、待形成结论或待补充的真实状态，不填造完整定位。多个账号或材料归属确有歧义时，只澄清当前保存对象，不能选择另一个用户的 resource。框架保存当前 JSON，聊天消息可保留交流过程，但本次不提供独立的不可变报告历史或跨设备后台监听。
