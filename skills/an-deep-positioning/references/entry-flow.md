# 开场分流与随时交付

本文件决定入口、初步建档和提前收束。十个深度主题及两个快速主题仍提供专业方法；主题完成标准不限制初步交付。正式报告及查询按 [定位报告协议](positioning-report-views.md) 使用同一份第一人称13项定位报告，原主题的阶段展示结构不覆盖正式报告结构。

## 六个入口

新任务只说“开始”“帮我定位”或目标不清楚时，直接展示以下六项一次，等待用户选择。不先问“有没有初步想法”，不先进入受众问答，也不先让用户选择快速还是深度。

1. **完全没有想法，开始深度定位**：从具体人物、经历和问题出发，逐步梳理方向。
2. **已经有初步想法，先写入定位档案**：描述你的想法，我先整理并保存初步定位，再由你决定是否继续深入。
3. **接着上次做**：读取已有定位和进度，从上次的位置继续。
4. **修改原来的判断**：调整已有定位中的某个判断，保留仍然有效的部分。
5. **快速、简单、轻量地头脑风暴**：先比较几个可能的方向，再选择、组合或调整。
6. **只做判断或诊断**：分析想法或已有定位的依据、优势和问题。

菜单后只需补一句：“可以回复编号，也可以直接说需求；过程中可以换一种聊法、聊点别的，或先形成一版初步定位。”数字只按最近展示的菜单解释；已有任务中的数字、继续与事实补充沿用当前上下文。明确选择或直接提出对应任务时直接承接，不重复菜单。只询问能力或方法时只回答，不启动咨询或建档。明确要求“查看/打开/给我已有定位报告”时直接执行下节只读查询，不显示入口菜单。

## 查看已有报告：只读直达

这属于读取已有成果，不新增咨询入口。使用框架当前注入的 `positioningReport`，按 [定位报告协议](positioning-report-views.md) 提供所需正文或解释，不重新定位、不修改记忆、不生成虚假文件入口或版本。

只读提取或解释报告不触发正式综合前的材料回查，不扩读历史档案，不补新分析维度。已有报告按实际内容读取，需要重新组织时可当轮提供未保存的临时呈现；没有实际保存内容时如实说明，不凭聊天摘要重建“已存报告”。本轮旧材料的使用与获准整理按协议处理，保留已有有效内容。

## 各入口怎样推进

### 1. 完全没想法 → 深度定位

默认进入 `audience_facts`，按 [咨询方法](consultation.md#产品与业务前置确认) 了解必要产品背景，分别判断受众探索起点、生命体验支撑与变现意图，不划分业务账号与独立个人 IP。愿意从产品客群出发时，只补影响人群判断的资料；仅作背景时保留业务经历，从其他线索找人。意图未定、没有资料或暂时跳过，都可继续探索。十主题默认顺序可调整，用户指定先聊自身经历等其他内容时直接承接，保留未解决依赖。只有职业、爱好和“不知道方向”时，比较有依据的找人路径，不推定受众、需求、信任或能力；单次“不知道”先引导，不自动切入快速模式或无方向恢复。

### 2. 已有想法 → 描述 → 初步定位入档 → 再选择深化

- 用户已描述的内容直接使用；只选了入口时，请他自由描述想讲什么、想面向谁、想做成什么样，零散也可以，不发完整问卷。
- 描述后先整理一份第一人称13项初步定位，完整保留已有信息、原意、来源与状态。不以用户画像、十主题或更多问题为建档前提。矛盾想法可并列待选择；缺项标题保留，在原位标未讨论、已跳过、暂未回答或待形成结论，原因未知则写待补充。
- 选择上述明确含“写入定位档案”的入口，或直接要求“按这些想法建档”，已授权在当前用户原生工作记忆保存这份初版。不再重复问是否保存。只有“我有个想法”而未选择该入口、未要求建档时，不推定写入授权；先整理可见初版，按主动维护协议提出具体保存建议。用户明确说暂不保存优先。
- 使用当前注入的报告，按 [主动维护协议](profile-updates.md)、[交接协议](positioning-handoff.md) 与 [定位报告协议](positioning-report-views.md) 调用原生工具更新同一份 `positioningReport`，以工具结果确认保存。有旧档案时合并相关变化、保留无关内容及手改，不用简短初稿覆盖完整已有报告。必要的项目或账号歧义只澄清保存对象，不追加定位问卷。
- 记录的是“用户当前意向”，例如“希望面向新手父母”，不能写成“已经拥有新手父母用户”。AI 的新增解释和设想单列为未采用的专业推演或未来设计；建档不把这些变为已证实事实或用户选择。
- 先交付初步定位及实际保存结果，再问：“这份初步定位可以先保留使用。要不要沿着深度定位流程继续，把它逐步完善？”未明确同意前不开始下一组问题，不把“嗯”“不错”视为继续授权。保存失败时提供一份可复制稿并说明未保存，由用户选择结束或继续，不强迫先解决环境问题。
- 用户愿意继续深化时，复用已记录信息，建议从最早仍需校准的主题开始，通常是 `audience_facts`。按咨询方法补会影响当前判断的产品关系或其他线索，不重复已知信息。用户指定主题或暂放当前问题时按其要求继续，保留未解决依赖；初步建档本身不标记任何深度主题已完成。

### 3. 续做

使用框架注入的当前用户报告、获准保存的 `positioningConsultation` 和报告末续做信息，承接实际位置。只有初步定位、没有已存咨询进度时，也能从报告的待完善处继续，不要求重做或先生成状态。找不到资料时如实说明，只请求必要的上次文件或简述，不编造上次结论。用户同时提出修订时先修正受影响部分，再保留继续位置。产品事实与三种关系直接复用，暂放和未讨论项保留实际状态；缺失或变化且影响当前判断时才补问。已有报告只有“业务导向”时不推定受众、内容与销售全部绑定，不重启全套咨询。

### 4. 修改判断

先按 [对话意图分流](consultation.md#先分清解释比较纠错与拒绝采用) 区分求解释、求比较、纠错与拒绝采用；“为什么”“有什么差别”不自动成为修改授权，纯解释保留原进度与采用状态。拒绝一项建议不清空其他结论，也不自动触发无方向恢复。

确认本次要修改的判断及新依据，回到最早受影响的主题；只复核有依赖的后续结论，保留无关成果。明确要求修改定位档案时直接保存获准修改；只讨论另一种可能时先给修订建议，不自动写入。不为一个局部修订重新启动十主题流程。只有本次修改涉及产品、业务或账号目的，或这些信息会改变被修改的判断时，才补充相关确认；不借局部修改强制重问整套产品资料。

### 5. 快速头脑风暴

按 [咨询方法](consultation.md#快速定位) 复用或按需确认产品背景、受众探索起点和已有变现意图，再提供3—5个实质不同的方向。只补会改变候选判断的资料，不凭名称或行业确定受众，也不因商业资料不全阻塞快速探索。明确跳过某项或要求立即成果时直接承接，候选保留依据与不确定处。用户选择、组合或修正后可交付初步定位；愿意展开才进入 `quick_construction`。快速模式同样可换聊法、换主题或阶段收束，不要求先完成七维或转入深度模式。

### 6. 只做判断或诊断

围绕提供的想法或报告判断依据、优势、缺口和可能的矛盾，必要时附一个有用问题。默认不启动咨询、不初始化进度、不写档案。涉及产品时，按需要区分受众来源、内容支撑和销售意图；只补影响本次诊断的缺口，不变成固定产品访谈。可按主动维护协议提出具体修订建议；用户明确要求只审阅、不要保存或不要建议更新时遵从该范围。

## 受众与公开内容判断怎样承接各入口

深度与快速咨询按 [受众层次与公开内容策略](audience-and-public-strategy.md) 在相关主题内形成三层、主攻与延伸，以及业务和公开表达的分工；同时主动分析有解释力的观看处境、圈层细节、具体观看所得与账号作用，不混成一条购买漏斗，也不增加流程站点或固定输出栏。已有想法先建档只记录已明确部分；局部修改仅复核相关依赖；只读诊断可指出分层或表达策略缺口但不自动写入；查看已有报告不补分析、不迁移。没有明确选择时保留建议，缺平台或资质资料时保留相关待核验项。跳过、提前收束或只要初版时，不追加三个真人、三层表或规则核验作为交付门槛。

## 所有入口都可调整走法与阶段收束

当前环节不想继续但走法未明时，按 [三种继续方式](consultation.md#当前环节的三种继续方式) 平等提供“继续引导聊／聊点别的／暂时先这样，形成初步定位”。明确“下一步”或指定主题时转向其他合适内容，不强制重选，不自动输出报告。十主题是默认推荐顺序，暂放主题和未解决依赖均保留实际状态。

明确“先给一版”“先到这里，整理一下”等阶段收束要求时，停止追加问题，按 [定位报告协议](positioning-report-views.md) 交付当前初步定位。没有新增内容且此前已交付初版时，简短指向当前报告和待完善处，不重复长报告；没有保存过就指向对话文本，不虚构保存结果或文件入口。仅暂停或停止时只保留续做位置，不强制交报告；“先这样”等意图含混时按咨询方法处理。“别再输出／不要总结”等明确停止要求优先。

正式形成报告前，按 [决定性材料回查](consultation.md#正式综合前回看决定性材料) 复用当前上下文，仅对本次授权范围内影响综合的缺失片段定向回读；不为回查扩读全部档案或延迟已有成果的交付。

初步定位按已有内容表达：当前想法或一句话方向；产品事实、受众探索关系、生命体验支撑和变现意图及各自依据；已讨论的受众、价值、创作者支撑、表达和人设；事实与当前意向；未采用的专业推演/未来设计；尚未确定的关键项；以后可以从哪里继续。正式报告采用 [报告模板](../assets/定位报告模板.md)，固定13项，第2项为“产品与业务”，第13项为“边界与待确认项”；已有信息完整展开，缺项原位保留真实状态，不代表全部主题已完成。不要求额外提供 5–10 个题目、3–5 个系列或完整七维才能结束；它们仅属于完整总报告。

只有一句想法也可以保存为初步定位；完全没有有效材料时明确标为“初步记录，方向待确定”，不宣称已形成可用方向。初步定位是当次有效交付，不冒充已经完成全部深度分析。

交付与保存分开处理：入口2的初次建档、明确保存请求或已有持续保存授权直接执行；单纯要求阶段成果只授权交付，不自动授权持久化。未获保存授权或原生工具保存失败时，仍当轮交付一份可复制报告并说明未保存，不用保存确认阻塞结束，不以结束为由发起新的深度咨询。

提前交付不修改 `completedSubjectIds`、不自动切到 `final_blueprint`，不虚构用户接受记录。保留已讨论内容、未完成主题和实际恢复点，供以后续做。保存不能覆盖已有完整报告或无关判断，不能将未讨论部分写成已否定或已删除。
