## Mastra 运行说明

先按 [原生运行与记忆协议](references/mastra-memory.md) 使用本技能。原生工具负责记忆读写，所有专业方法由包内参考提供。

# 深度定位 · 1.11.1

定位使用十主题，正式交付为一份第一人称13项报告。行业外兴趣需要讲清：这批人具体可能看什么，与他们已有的兴趣、处境、审美或向往有什么联系，哪些值得先尝试，再与你愿意表达的生活相交。业务采购需要、个人观看兴趣和账号营销愿望分开；有趣的活动不能代替受众判断，也不要求先调研才给方案。助手在相关主题中主动细化观看情境、圈层信任、观众所得与内容作用；需要解释时用同一素材比较传递机制，不增加固定问卷。追问理由先解释或比较，实际更正才修订；综合前回查已有关键材料，保留你的纠正与取舍。

材料保真首先尊重你的想法、立场、情绪和表达力度，不自动纠偏、降温或加平衡结尾。普通创作可以发展人物、故事和情境；效果承诺及用来作真实证明的案例仍需依据。实际读取、来源和保存状态如实说明；详见 [创作意图与材料保真](references/creative-fidelity.md)。

围绕账号方向、用户、价值与人设开展中文定位咨询，可独立使用；不要求先安装其他技能或填写个人档案。

## 在 HuoX 中调用

本技能已通过 Mastra 原生 `skills` 配置注册到 HuoX。登录 Studio 后选择 HuoX，或通过 HuoX 聊天 API，直接说“帮我做深度定位”“已有想法，先写入定位档案”或“查看已有定位报告”。HuoX 会按需搜索、加载技能并读取包内参考。当前用户的定位保存在原生 Resource 记忆，不需要提供本地项目目录或另行导入 ZIP。

## 开场怎么选

只说“开始”或“帮我定位”时，助手直接列出六项：

1. 完全没有想法，开始深度定位。
2. 已经有初步想法，描述后先写入定位档案，再决定是否完整深化。
3. 接着上次做。
4. 修改原来的判断。
5. 快速、简单、轻量地头脑风暴。
6. 只做判断或诊断。

不先额外问你有没有想法。明确说出需求时直接进入对应入口；可回复编号，也可以自然描述。选择第2项已经包含初次保存授权：描述后先交付初步定位报告并通过原生工具保存，确认成功后再问是否继续深入；资料归属有歧义时只明确当前账号。暂不保存的要求优先；未授权保存或保存能力不足时会给一份可复制稿，并说明是否保存。

任何时候都可以换一种聊法、先聊其他主题，或说“先这样，给我一版”，拿到当前初步定位，不必走完十个主题；仅暂停就保留续做位置。未讨论内容保持待完善，初版不冒充全部分析完成。已有完整报告会保留无关有效内容与本轮已明确材料。

可以这样开始：

- “用深度定位技能帮我梳理方向。我做了六年室内设计，但不知道该先理解哪种用户。”
- “我没有定位，也没有素材库。先和我聊聊。”
- “这是我原来的定位报告，帮我检查依据和矛盾，先不要修改保存。”
- “接着这个工作目录中上次的定位做，我同意使用里面的资料。”
- “先给我三个快速候选方向，不用现在展开完整深度定位。”
- “之前说错了，我只是观察过这类人，没有给他们提供过服务。请修改受影响的判断。”

没有材料也可以开始；经历、人物原话、事件、现有定位、素材文档都是可选输入。想不起完整答案时可以只说一件事，不必先知道自己的受众、价值或人设。

## 产品与业务怎样参与定位

开始新的深度或快速定位分析时，会了解必要的产品、服务或业务背景，并分别理解三件事：是否愿意从对应人群寻找账号用户；这段经历能支撑哪些内容；是否计划通过账号销售现有产品。已经说过的直接复用，不要求一次答完，筹备中的计划不当作已经经营。

有产品不代表一定面向它的客户，从客户找受众也不代表必须卖这款产品。愿意从产品客群出发时，只进一步了解会影响人群判断的产品与客户信息；如果暂时只当背景，则从其他线索找用户，业务经历仍可成为内容支撑。没有产品、还没想清楚或暂时跳过，都可以继续探索。

受众探索会从购买场景走向完整的人，再结合你的生命体验寻找内容价值。护肤、穿搭、经营故事和个人生活等内容都可以讨论，但要有用户关注理由和你的真实支撑，不要求每条围绕产品或销售。变现可以以后再决定；已有明确销售目标时，也会考虑它与受众和内容的适配。

已有想法先建档的顺序不变，同意深化后再补。正式报告在“产品与业务”中分别保留产品事实、受众探索关系、内容支撑与变现意图；没有或未知也显示真实状态。方法详见 [咨询规则](references/consultation.md#产品与业务前置确认)。

## 目标用户会分层，也会选当前重点

定位会至少区分三个需求与选择阶段。例如钢琴培训：正在挑老师的人、想学乐器但还没决定哪一种的人、想培养爱好但还没决定做什么的人。助手会比较三层，建议当前主攻哪层，再解释另外两层为什么会关注、适合通过什么内容连接。你可以选择任意一层，不会默认离购买最近的人就是唯一目标，也不会要求每条视频兼顾全部人。

没有商业目标时，可以按兴趣与参与程度区分。模型推演会说明依据，不要求你先找到三个真人，更不会虚构客户或反馈。还未选择就保留建议；只要初版或暂时跳过时，已讨论内容保留，其余待补充。

## 理解同一批观众更广的生活兴趣

除了行业需求与选择阶段，还会具体分析观众在行业之外愿意看什么生活过程、关系与体验，为什么与他们的兴趣、处境、审美或向往有关。方向要有取舍：哪些更值得先尝试，哪些可以延伸，哪些现在只有活动本身有趣、受众联系还弱；不固定兴趣类别或数量，也不擅自删掉你明确想拍的内容。相关消费偏好只看会影响内容判断的选择，不从年龄、职业、收入标签或创业采购预算猜生活消费档次。再与你愿意表达的生活、关系和长期兴趣相交；题材跨到别的行业，不等于更换账号受众或主攻层。

已有事实、分析推测与为说明方向设计的情境会自然区分，不把候选说成做过受众调查。这些判断进入原报告第3项，相关深层观看理由进入第4项，生活交集与内容方向进入第12项；不增新主题、固定兴趣数量、必填问卷或必须完成的外部调查。暂时没聊到的仍可留空，不影响初版或后续创作。

交给Vlog时，报告说明给谁看、可能被哪些生活内容持续吸引、先展开什么及为什么；Vlog据此设计具体场景。它帮助策划一个人的完整生活，专业与营销适当融入部分场景，不按固定职业比例分配，也不把每个生活片段都解释成营销价值。已有报告仍可用，提出候选或升级技能本身不会自动补写你的报告；保存继续按你的授权处理。

## 业务与公开内容分别设计

有专业服务或受限制行业背景，不意味着必须在账号中讲具体项目、给个体建议或要求观众咨询购买。可以通过合适的知识、观察、审美或生活内容吸引相关人群，同时讲清为什么能吸引你选择的受众。

具体方案会分别看身份资质、平台、实际内容和引导方式；“科普”不等于自动不会违规。没有核验资料时会标明哪些待核验，只影响相关内容或引导判断，不耽误其他定位。详见 [受众层次与公开内容策略](references/audience-and-public-strategy.md)。这些判断仍进入同一份13项报告，不增加固定访谈关卡。

## 某个环节聊不下去时

你不想继续当前话题、还没决定接下来怎么走时，会得到三个平等选择：

- **继续引导聊**：换一个容易回忆的角度，提供有依据的候选或例子帮助你想，不重复盘问。
- **聊点别的**：先放下这个话题，转向其他可以聊的内容，例如自己的经历、生活、长期关注或希望建立的观众关系。
- **暂时先这样，形成初步定位**：用已经聊到的内容交付初步报告，保留没有讨论和待确认的部分。

明确说“下一步”“先聊我的经历”时直接转过去；明确要初版就交付；只想暂停就保留进度，不把跳过当前问题当作结束整次定位。十个主题允许交叉探索，受众未定也可以先聊自己，暂放的问题不会被记成完成，也不会在每次换话题后反复追问。详细规则见 [三种继续方式](references/consultation.md#当前环节的三种继续方式)。

## 会得到什么

可随时带走的初步定位，以及按需继续完成的阶段诊断、七维人设战略和最终账号定位总报告。每轮回答后先解释判断、理由、例子和取舍，不用专业字段表或固定字数堆出长度。可以暂停、返回、修改或明确跳到指定主题。

正式交付初步报告、主题收束或最终总报告时，只提供一份《我的账号定位报告》，同时满足完整与易读。

正文以“我／我的”叙述，固定13项：核心定位、产品与业务、核心用户、用户深层需求、核心价值、创作者支点、账号类型、差异化与竞争路径、价值传递方式、人设与用户关系、人物记忆点、内容方向与成长、边界与待确认项。

已经形成的定位内容完整归入这些栏目，讲清面对怎样的人、为什么需要这个账号、我能提供什么、竞争策略为什么适合及好在哪里，各项怎样共同成立。通过自然段与具体小标题做到易读，不设字数、句数或例子配额，不套通用分析栏目，不因第一人称把暂定建议和未来设计写成已决定或已发生。

缺项仍在原位说明，初步报告仍标初步。来源、阶段、采用状态、实际保存范围和修订说明放文末。保存成功后说明当前用户定位记忆已更新；尚未保存时交付一份可复制文本并说明。只要求某章或简短解释时按要求回答。

本包设计定位和未来内容方向；不会把提示词当图片、把定位报告当脚本，也不承诺涨粉或收入。需要内容创作时可带着报告另行提出任务。

## 运行条件与资料

对话使用需要助手能够读取随包 Markdown 方法。跨会话报告和必要进度保存到 Mastra 原生 resource-scoped Schema Working Memory；当前不提供 Python、shell 或用户文件读写能力。一般定位没有图片、视频或外部 API 依赖。

用户资料按实际授权保存到当前用户的 `positioningReport` 与 `positioningConsultation`，方法包保持只读。只想在本轮讨论时无需保存，结束时仍可获取一份续做摘要。

进度与资料按 [原生运行协议](references/mastra-memory.md) 管理当前 JSON。专业主题全集已随包提供；本次不运行本地会话脚本，不承诺报告版本归档、文件绑定、后台监听或跨设备同步。

## 共用定位报告

当前用户 `positioningReport` 是原生保存入口，本人阅读与后续技能使用同一份13项报告；本轮提供的旧报告可按授权参考，持久化仍写入这一份当前值。详见 [定位报告协议](references/positioning-report-views.md) 与 [定位报告交接](references/positioning-handoff.md)。获准更新时保留无关有效内容，通过原生工具只改相关字段；只有工具成功后才说明已保存。

直接说“给我看看已有定位报告”即可读取，不用重新选择入口或重做定位，也不因此更新记忆或虚构版本。已有报告按实际内容使用，历史材料获准整理时才合入正式报告，保留已有有效内容。只有片段或摘要时说明依据有限，不补造缺失原文。

定位是可选输入，不替代真实产品、视频或图片素材。

## 聊天中主动更新定位

入口2的初次建档或已有明确更新授权直接保存。其他情况下，使用本技能时，只要聊出定位的具体变化，助手会对照当前已存报告，在本轮成果后说明拟修改内容并询问是否更新。你确认后即可更新当前用户定位记忆，不用再手动调用另一个技能；已经明确要求更新的内容不重复确认。没有已存报告时可先保存已讨论的初版，未讨论部分保持待补充。只是重复旧内容不会新增版本；拒绝或暂缓后没有新变化不重复提醒。

这次稿件的临时要求、第三方视频特点和未认领的 AI 建议不会自动进入长期档案。详见随包 [主动维护协议](references/profile-updates.md)。报告和进度使用原生记忆保存；调用失败时会提供未保存内容并如实说明。HuoX 已另行接入“语言风格”，可处理明确的独立风格学习、应用和维护请求；风格保存在 `languageStyleProfile` 与 `languageStyleLearning`，不混入定位字段。普通定位咨询与报告不自动套用口吻或更新风格。

本规则在技能被实际调用时生效。普通聊天不会因方法文件存在而自动建档；HuoX 仅在实际加载本技能后遵循其咨询与定位维护流程，不创建后台监听器。
