# 轻量发布诊断历史记录

本文记录已退役的 Agent Compose 发布及当时的故障证据。当前发布准备见[标准发布](standard-release.md)。

现有发布命令、五阶段和失败结果保持原流程。宿主在执行检查时记录固定检查名；失败终态增加可选的 `diagnostic: { check, code, exitCode? }`。Actions 在同一 Job 中解析并显示检查项、静态说明和下一步，保留准确 invocationId，便于后续只读查询原调用。它不是模型推理或自动修复。

## 开销和边界

| 项目 | 正常发布 | 失败时 |
| --- | --- | --- |
| Job、云调用、IAM、付费模型 | 无新增 | 无新增 |
| 远端输出 | 原有进度和终态 | 最长诊断对象额外约 90 字节；总上限仍为 4096 字节 |
| Actions 结果 | 当前调用 ID 约增加 35 字节 | 额外固定检查项、错误码、可选退出码、诊断可用状态和静态下一步 |
| 时间 | 少量本地赋值、校验与渲染 | 不读取/扫描远端日志、不另等网络或模型；无额外超时预算 |
| 日志存储 | 无新 artifact | 原始日志仍保留在 Agent 私有状态目录，不上传正文 |

非法诊断被丢弃并标明 invalid；缺失时标明 missing。已验证的原发布失败、阶段和调用 ID 保留。实例/命令/调用/SHA 校验或基础终态非法仍拒绝。不会因诊断失败重发发布、取消远端调用、改配置或掩盖原发布结果。只有明确命中的固定分类才给出对应说明，不从阶段猜测根因。

已授权的只读诊断由执行任务的 Agent 自行完成，限制于固定测试机、本项目发布状态目录与本项目容器。临时人工排查可能产生额外只读云调用和等待，其成本与本表中的自动发布路径分别报告。一个本地 STS 获取失败不等于所有读取权限都不可用；在已有授权内核验其他入口，不创建长期凭据或扩大 workflow 角色。
